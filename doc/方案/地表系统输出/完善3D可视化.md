# 完善3D可视化

## 一、总体架构：从数据到可探索的3D世界

3D可视化是虚拟世界生成器的**最终呈现层**。它需要将前序所有阶段输出的网格数据（地形高程、温度、降水、气压、风场、洋流、生物群系、土壤、农业类型）转化为可**交互探索**的三维球面场景。

总体架构分为四层：

**第一层：球面网格与坐标系统**。将等经纬度或立方球网格数据映射到三维球面，建立统一的三维空间参考系。

**第二层：地形渲染**。基于层级细节（LOD）策略，将高分辨率地形数据实时渲染为三维网格，保证裂缝-free和视觉连续性。

**第三层：物理光照与大气**。基于物理的光照模型（PBR）和大气散射模型，模拟太阳照射、天空颜色和大气透视。

**第四层：气候数据叠加**。将温度、降水、气压、洋流等气候场通过纹理映射、颜色编码、流线动画等方式叠加到球面上。

在 MacBook Pro 2024（Apple Silicon）上，核心渲染采用 **VTK 9.7 + PyVista**（Metal后端）或 **mlx3D**（MLX原生Metal kernel），地形数据的GPU预处理采用 **MLX**，流线计算采用 **Numba JIT**。


## 二、第一层：球面网格与坐标系统

### 2.1 三维球面坐标的数学定义

三维世界使用**行星中心坐标系**：原点位于行星质心，\( z \) 轴指向北极，\( x \) 轴指向本初子午线与赤道的交点。任意球面点由经纬度 \( (\lambda, \phi) \) 映射为：

\[
\mathbf{p}(\lambda, \phi, r) = r \begin{pmatrix} \cos\phi \cos\lambda \\ \cos\phi \sin\lambda \\ \sin\phi \end{pmatrix}
\]

其中 \( r = R + H(\lambda, \phi) \) 是径向距离，\( R \) 是行星参考半径，\( H \) 是高程。

**椭圆体修正**：真实行星通常因自转而呈椭球形。参考半径随纬度的变化为：

\[
R(\phi) = \frac{a}{\sqrt{1 - e^2 \sin^2\phi}}
\]

其中 \( a \) 是赤道半径，\( e = \sqrt{1 - b^2/a^2} \) 是偏心率（\( b \) 为极半径）。对于虚拟行星，如果自转速率较高（如快速旋转的系外行星），椭率会显著增大。

### 2.2 立方球网格到球面的映射

立方球网格的6个面通过**球面投影**映射到球面。推荐使用**切向投影**（Tangential Spherical Cube），即从立方体中心向球面做径向投影：

对于立方体面 \( f \) 上的点 \( (u, v) \in [-1, 1]^2 \)，投影到球面的单位向量为：

\[
\mathbf{n} = \frac{\mathbf{c}_f + u \mathbf{e}_{f,u} + v \mathbf{e}_{f,v}}{\|\mathbf{c}_f + u \mathbf{e}_{f,u} + v \mathbf{e}_{f,v}\|}
\]

其中 \( \mathbf{c}_f \) 是面 \( f \) 的中心方向，\( \mathbf{e}_{f,u}, \mathbf{e}_{f,v} \) 是面内的两个正交基向量。这保证了**球面无缝连续**，且极点附近**无畸变**——球面噪声在 \( (x, y, z) \) 笛卡尔坐标上采样，而非从平面投影，因此没有极点畸变。

### 2.3 坐标转换的精度问题

在GPU上进行球面细分时，**单精度浮点误差**会在高细分级别导致视觉伪影。解决方案是采用**泰勒级数近似**计算相对于观察者的椭球面位置。具体地，对于观察者附近的球面点 \( \mathbf{p}_0 \)，其邻域内的球面点 \( \mathbf{p} \) 满足：

\[
\|\mathbf{p}\| = R(\phi)
\]

用泰勒展开近似：

\[
\mathbf{p} \approx \mathbf{p}_0 + \delta \mathbf{p} + \frac{1}{2}\delta\mathbf{p}^T \mathbf{H} \delta\mathbf{p}
\]

其中 \( \mathbf{H} \) 是球面在 \( \mathbf{p}_0 \) 处的Hessian矩阵。这避免了直接计算 \( \mathbf{p} = R(\phi) \hat{\mathbf{n}} \) 时的浮点精度损失。

**双精度回退策略**：在极端近距离（如视角高度 < 100 m）时，将相机附近的局部网格切换到双精度计算，其余部分保持单精度。


## 三、第二层：地形渲染与LOD

### 3.1 LOD层次结构：UDLOD与Chunked Clipmap

**统一距离相关层级细节**（Uniform Distance-Dependent LOD，UDLOD）是当前球面地形渲染的最优方案。其核心思想是：根据网格单元到观察者的**世界空间距离**确定细分级别，保证屏幕空间误差均匀。

**Chunked Clipmap**是UDLOD的数据结构载体。它将球面地形划分为嵌套的**同心区域**，每个区域由一个**四叉树**管理，但只保留当前视图需要的层级。

**UDLOD的核心参数**：

| 参数 | 含义 | 推荐值 |
|------|------|--------|
| `view_distance` | 可见距离（网格单元数） | 4–8 |
| `grid_size` | 每层网格分辨率 | 4–8 |
| `pixels_per_quad` | 每四边形像素数 | 2–4 |

最终基准测试显示，在**全高清分辨率 + 4×MSAA + 16×各向异性过滤**下，200万顶点场景的GPU时间约 **14.6 ms**（约68 FPS），500万顶点场景约 **27.2 ms**（约37 FPS），670万顶点场景约 **32.9 ms**（约30 FPS）。

### 3.2 裂缝消除与顶点形变

LOD过渡时的**裂缝**和**跳变**是地形渲染的核心难题。解决方案是**顶点形变**（Vertex Morphing）：在LOD切换时，顶点的位置在旧级别和新级别之间**平滑插值**。

对于四叉树中的节点 \( n \)，其形变因子为：

\[
\alpha = \text{clamp}\left( \frac{d_{\text{view}} - d_{\text{threshold}}}{d_{\text{transition}}} , 0, 1 \right)
\]

顶点位置为：

\[
\mathbf{p}_{\text{morph}} = (1 - \alpha) \mathbf{p}_{\text{coarse}} + \alpha \mathbf{p}_{\text{fine}}
\]

当 \( \alpha \) 从0到1变化时，顶点从粗级别平滑过渡到细级别，**裂缝消失，跳变消除**。

**裂缝-free约束**：相邻网格块的LOD级别差不超过1（即 \( |L_i - L_j| \leq 1 \)）。这可以通过在四叉树遍历时强制邻域一致性来实现。

## 四、第三层：物理光照与大气散射

### 4.1 基于物理的渲染（PBR）

地形表面的着色采用**Cook-Torrance微表面模型**：

\[
L_o = \int_{\Omega} (k_d \frac{c}{\pi} + k_s \frac{D \cdot F \cdot G}{4 (\mathbf{n}\cdot\mathbf{l})(\mathbf{n}\cdot\mathbf{v})}) L_i (\mathbf{n}\cdot\mathbf{l}) d\omega_i
\]

其中：

- **法线分布函数** \( D \)（GGX/Trowbridge-Reitz）：

\[
D(\mathbf{h}) = \frac{\alpha^2}{\pi ((\mathbf{n}\cdot\mathbf{h})^2 (\alpha^2 - 1) + 1)^2}
\]

- **菲涅尔项** \( F \)（Schlick近似）：\( F = F_0 + (1 - F_0)(1 - \mathbf{v}\cdot\mathbf{h})^5 \)

- **几何遮蔽** \( G \)（Smith方法）

**地形材质的参数化**：不同地表类型（岩石、土壤、雪、植被）有不同的 \( F_0 \)、粗糙度 \( \alpha \) 和反照率 \( c \)。这些参数从**生物群系和土壤类型**自动映射：

| 地表类型 | \( F_0 \) | 粗糙度 | 反照率 |
|---------|----------|--------|--------|
| 岩石 | 0.04 | 0.7–0.9 | 0.15–0.25 |
| 土壤 | 0.03 | 0.9–1.0 | 0.10–0.20 |
| 雪/冰 | 0.02 | 0.2–0.4 | 0.60–0.80 |
| 植被 | 0.04 | 0.6–0.8 | 0.10–0.25 |

### 4.2 大气散射：Bruneton预计算模型

**Bruneton的预计算大气散射模型**是物理精确的天空渲染标准。它将大气假设为球壳中的**指数分布介质**，考虑**瑞利散射**、**米氏散射**和**臭氧吸收**。

**瑞利散射系数**：

\[
\beta_R(\lambda) = \frac{8\pi^3 (n^2 - 1)^2}{3 N \lambda^4}
\]

其中 \( n \) 是空气折射率，\( N \) 是分子数密度，\( \lambda \) 是波长。瑞利散射的**\( \lambda^{-4} \)依赖**是天空蓝色的物理根源。

**米氏散射系数**：\( \beta_M \) 由气溶胶浓度决定，**与波长弱相关**（通常 \( \lambda^{-1} \)）。米氏散射产生天空的**白色调**（云、雾）。

**大气透射率**为：

\[
T(\mathbf{x}, \mathbf{y}) = \exp\left( -\int_{\mathbf{x}}^{\mathbf{y}} (\beta_R + \beta_M + \beta_O) ds \right)
\]

**预计算策略**：Bruneton模型的核心创新是将**透射率**和**散射**预计算为二维纹理查找表。透射率存储为 \( (r, \mu) \) 的二维表，其中 \( r \) 是高度，\( \mu \) 是方向余弦。运行时通过**双线性插值**查询，实现实时性能。

**在MacBook Pro上的实现**：用MLX GPU预计算散射查找表：

```python
import mlx.core as mx

def precompute_scattering_gpu(R_atm, H_atm, n_r, n_mu):
    """
    MLX GPU: 预计算大气散射查找表
    R_atm: 行星半径 (m)
    H_atm: 大气标高 (m)
    """
    r = mx.linspace(R_atm, R_atm + H_atm, n_r)
    mu = mx.linspace(-1, 1, n_mu)
    
    # 计算光学深度
    optical_depth = compute_optical_depth(r, mu, H_atm)
    
    # 瑞利散射
    beta_R = 5.8e-6 * (550e-9)**4 / wavelength**4  # 简化
    tau_R = beta_R * optical_depth
    
    # 米氏散射
    beta_M = 2e-5
    tau_M = beta_M * optical_depth
    
    # 透射率
    transmittance = mx.exp(-(tau_R + tau_M))
    
    return transmittance
```

M4 Max GPU处理 256×128 的散射查找表约 **2–5 ms**。

## 五、第四层：气候数据叠加

### 5.1 纹理映射的数学

气候数据（温度、降水、气压）通过**纹理映射**叠加到球面：

\[
(u, v) = \left( \frac{\lambda + \pi}{2\pi}, \frac{\phi + \pi/2}{\pi} \right)
\]

**Cube-sphere纹理**避免了极点畸变：每个立方体面有独立的 \( (u, v) \) 纹理坐标，通过切向投影映射到球面。

**温度纹理的颜色编码**使用**感知均匀色图**（如RdBu_r）：

\[
\text{color}(T) = \text{RdBu\_r}\left( \frac{T - T_{\min}}{T_{\max} - T_{\min}} \right)
\]

### 5.2 流线动画的物理模型

气压带风带和洋流的**流线动画**基于**粒子追踪**。对于风场 \( \mathbf{u}(\lambda, \phi) \)，粒子位置 \( \mathbf{x}_i \) 满足：

\[
\frac{d\mathbf{x}_i}{dt} = \mathbf{u}(\mathbf{x}_i)
\]

用**四阶Runge-Kutta**数值积分：

\[
\mathbf{x}_{n+1} = \mathbf{x}_n + \frac{h}{6}(\mathbf{k}_1 + 2\mathbf{k}_2 + 2\mathbf{k}_3 + \mathbf{k}_4)
\]

其中 \( \mathbf{k}_1 = \mathbf{u}(\mathbf{x}_n) \)，\( \mathbf{k}_2 = \mathbf{u}(\mathbf{x}_n + \frac{h}{2}\mathbf{k}_1) \)，依此类推。

**球面流线的特殊处理**：粒子在球面上运动，需要**约束在单位球面**上。每步积分后，将粒子投影回球面：

\[
\mathbf{x}_{n+1} \leftarrow \frac{\mathbf{x}_{n+1}}{\|\mathbf{x}_{n+1}\|}
\]

**流线的视觉编码**：

- **线宽**：\( w = w_0 + k \cdot |\mathbf{u}| \)
- **颜色**：速度大小或温度
- **箭头**：沿流线周期性放置，间距 \( d \approx 5w \)

### 5.3 气压场的等值面渲染

气压场 \( p(\lambda, \phi) \) 的**等值面**（如 1000 hPa、1013 hPa、1020 hPa）可以用**Marching Cubes**算法在三维空间中提取。对于球面气压场，等值面的数学定义为：

\[
p(\lambda, \phi) = L
\]

其几何形态为球面上的一系列闭合曲线，通过**球面Marching Squares**提取后映射到三维空间。

### 5.4 海洋表面的波浪效果

海洋表面的**视觉波浪**由**Gerstner波**模型产生：

\[
\begin{aligned}
x &= x_0 + \sum_{i} \frac{Q_i A_i}{k_i} \cos(k_i \cdot (x_0, z_0) - \omega_i t + \phi_i) \\
y &= y_0 + \sum_{i} A_i \sin(k_i \cdot (x_0, z_0) - \omega_i t + \phi_i)
\end{aligned}
\]

其中 \( Q_i \) 是陡峭度参数，\( k_i \) 是波数，\( \omega_i \) 是角频率。Gerstner波产生**尖峰波谷**的海洋表面，比正弦波更真实。

**物理约束**：波浪的**色散关系**为 \( \omega^2 = gk \tanh(kH) \)，其中 \( H \) 是水深。在深海（\( kH \gg 1 \)），\( \omega = \sqrt{gk} \)；在浅海，\( \omega = k\sqrt{gH} \)。


## 六、加速方案（MacBook Pro 2024）

### 6.1 渲染架构选择

**方案A：VTK 9.7 + PyVista（推荐用于数据分析）**

VTK 9.7 引入了**平台无关的图形架构**，在Apple平台上通过 **Metal 后端** 与 Cocoa 集成。这意味着PyVista可以直接利用M4的GPU进行渲染，无需OpenGL转换层。

**注意事项**：PyVista对VTK的封装可能引入额外的渲染调用开销（有报告显示PyVista的渲染调用次数是纯VTK的112倍，导致4–5倍性能下降）。缓解策略：

- 使用`plotter.render()`手动控制渲染时机
- 对于静态场景，使用`plotter.screenshot()`替代交互式渲染

**方案B：mlx3D（推荐用于MLX原生渲染）**

mlx3D提供了**Apple Silicon原生的可微分3D渲染**，支持**网格渲染**（可微分软三角形光栅化、UV纹理采样）和**3D高斯溅射**（Metal翻译的CUDA光栅化器，约30 FPS @ 720p，10万个高斯点）。对于虚拟世界生成器，mlx3D的**网格渲染**路径可以直接用于地形网格的GPU渲染。

### 6.2 地形网格的GPU预处理

用MLX在GPU上完成地形网格的构建、法线计算和LOD生成：

```python
def compute_terrain_normals_gpu(elevation, R):
    """MLX GPU: 地形法向量计算"""
    dz_dx = mx.gradient(elevation, axis=1)
    dz_dy = mx.gradient(elevation, axis=0)
    
    # 球面法向量修正
    lat = mx.linspace(-mx.pi/2, mx.pi/2, elevation.shape[0])
    lat_grid = mx.broadcast_to(lat[:, None], elevation.shape)
    
    # 切向量
    tangent_x = mx.stack([-mx.sin(lat_grid), mx.cos(lat_grid), mx.zeros_like(lat_grid)], axis=-1)
    tangent_y = mx.stack([mx.zeros_like(lat_grid), mx.zeros_like(lat_grid), mx.ones_like(lat_grid)], axis=-1)
    
    # 法向量
    normals = mx.cross(tangent_x + dz_dx[..., None] * tangent_y, 
                       tangent_y + dz_dy[..., None] * tangent_x)
    normals = normals / mx.linalg.norm(normals, axis=-1, keepdims=True)
    
    return normals
```

在M4 Max上，1000×1000网格的法向量计算约 **3–5 ms**。

### 6.3 LOD切换的GPU加速

UDLOD的**四叉树细分**可以在GPU上并行执行。每个四叉树节点的细分决策基于**屏幕空间误差**：

\[
\text{SSE} = \frac{\text{几何误差} \cdot \text{屏幕高度}}{\text{节点距离} \cdot 2 \tan(\text{FOV}/2)}
\]

当 \( \text{SSE} > \text{阈值} \) 时细分节点。GPU实现使用**并行前缀和**计算每个节点的累积误差，然后用**原子操作**更新四叉树结构。

### 6.5 流线动画的GPU加速

流线积分是**串行依赖**的（每步依赖上一步的位置），但多条流线可以**并行**。用Numba JIT编译：

```python
@njit(parallel=True, fastmath=True, cache=True)
def integrate_streamlines_gpu(u, v, seeds, h, max_steps):
    """并行积分多条流线"""
    n_seeds = seeds.shape[0]
    streamlines = np.zeros((n_seeds, max_steps, 3))
    
    for k in prange(n_seeds):
        x, y = seeds[k, 0], seeds[k, 1]
        streamlines[k, 0] = [x, y, 0]
        for step in range(1, max_steps):
            # RK4 积分（在球面上）
            k1 = interp_sphere(u, v, x, y)
            k2 = interp_sphere(u, v, x + h*k1[0]/2, y + h*k1[1]/2)
            k3 = interp_sphere(u, v, x + h*k2[0]/2, y + h*k2[1]/2)
            k4 = interp_sphere(u, v, x + h*k3[0], y + h*k3[1])
            dx = h/6 * (k1[0] + 2*k2[0] + 2*k3[0] + k4[0])
            dy = h/6 * (k1[1] + 2*k2[1] + 2*k3[1] + k4[1])
            x += dx; y += dy
            # 投影回球面
            norm = np.sqrt(x**2 + y**2 + 1.0)
            x /= norm; y /= norm
            streamlines[k, step] = [x, y, 0]
            if out_of_bounds(x, y):
                break
    return streamlines
```

## 八、验证与保真度

### 8.1 几何保真度

- **顶点形变连续性**：LOD切换时，屏幕空间误差应保持均匀
- **裂缝-free**：相邻网格块之间无可见缝隙
- **法向量一致性**：地形法向量在LOD边界处连续

### 8.2 光照保真度

- **能量守恒**：PBR着色器的反射光通量不超过入射光通量
- **大气散射**：日落时天空颜色从蓝到橙红的过渡应物理正确
- **阴影**：地形自遮挡产生的阴影方向应正确

### 8.3 地理合理性

- **气候纹理一致性**：温度纹理的纬度分布应与辐射强迫一致
- **流线物理一致性**：风场流线应大致平行于等压线
- **海洋渲染**：洋流流线不应穿越陆地

### 8.4 与真实地球对比

在地球参数下运行3D可视化，检查：

- 从太空看地球的**蓝色大气边缘**
- 日落时天空从**蓝色到橙红色**的渐变
- 云层的**白色**和**半透明**效果
- 海洋的**深蓝色**和**太阳耀斑**


## 九、实践建议

**先低分辨率跑通**。用 1° 分辨率的地形和气候数据构建3D场景，验证渲染管线的正确性。然后用0.1°或更高分辨率测试LOD性能。

**缓存预计算结果**。大气散射查找表、地形法向量、LOD四叉树结构都是静态的，用Zarr或二进制格式缓存，避免每次启动时重新计算。

**LOD策略调优**。根据MacBook Pro的GPU性能，调整`view_distance`、`grid_size`和`pixels_per_quad`参数，在视觉质量和帧率之间找到平衡。

**多平台兼容**。VTK 9.7 的Metal后端使代码在Apple Silicon上原生运行，同时保持与Windows（Direct3D）和Linux（Vulkan）的兼容性。

**交互优先**。3D可视化的核心价值在于**探索**。优先保证交互流畅（> 30 FPS），其次才是渲染质量的极致追求。
