# 地形生成混合方案与程序加速策略

## 一、混合地形生成方案

### 1.1 总体思路：三层混合架构

混合方案的核心是在**不同尺度上使用不同方法**，每层方法负责生成该尺度最擅长的特征，层与层之间通过数据接口衔接：

**第一层：构造层（宏观，10–100 km 尺度）** —— 用板块构造模拟生成大陆轮廓、山脉走向、海陆分布的基本格局。这一层决定世界的“骨架”，必须物理合理。

**第二层：精修层（中观，1–10 km 尺度）** —— 用 Terrain Diffusion 扩散模型或分形噪声精修构造高程，生成真实的山地起伏、沟谷纹理。这一层决定世界的“皮肤”。

**第三层：雕刻层（微观，100 m–1 km 尺度）** —— 用水力侵蚀和热力侵蚀模拟河流切割、坡面冲刷、沉积物堆积，生成河谷、冲积平原、峡谷等地貌。这一层决定世界的“皱纹”。

这三层的输出叠加后形成最终高程场：`H_final = H_tectonic + H_diffusion_refine + H_erosion`。关键在于，第二层和第三层**不改变第一层建立的宏观格局**（海陆边界、主要山脉位置），只在其基础上添加细节。


### 1.2 第一层：板块构造模拟

#### 1.2.1 球面 Voronoi 板块划分

在球面上生成板块，不能直接用平面 Voronoi。标准做法是：

**步骤一**：在单位球面上生成 N 个随机点（N 通常取 200–500），作为板块“种子点”。可以使用球面均匀采样（如 Fibonacci 球面分布或 Marsaglia 方法）避免极点聚集。

**步骤二**：计算球面 Voronoi 图。每个网格单元归属于距离其最近的种子点。球面 Voronoi 的计算可以用 `scipy.spatial.SphericalVoronoi`（SciPy ≥ 1.12）或自行实现基于大圆距离的最近邻查询。

**步骤三**：**域扭曲**。直接 Voronoi 的边界过于规则，缺乏自然感。对每个网格单元的经纬度施加一个分形噪声扰动后再计算最近种子点，使板块边界变得蜿蜒曲折。这就是 Klisuaiji/earthengine 项目采用的“域扭曲球面 Voronoi”方法。扰动强度控制边界的曲折程度，通常取板块平均边长的 10%–20%。

**步骤四**：**微板块归并**。上一步产生的是微板块（200–500个），数量太多且不符合真实板块构造的尺度分布。随机选择 6–12 个微板块作为“大板块核心”，然后将邻近微板块按照“距离最近 + 共享边界最长”的规则归并到大板块。Klisuaiji 的项目正是“生成微板块并归并为 6 大板块”。

#### 1.2.2 板块运动与边界类型

每个板块赋一个**欧拉极点**和**角速度**，定义其球面上的刚体运动。两个相邻板块的相对运动速度由欧拉矢量差决定：

`v_rel = (ω₁ - ω₂) × r`

其中 `r` 是边界点位置矢量。根据相对运动方向与边界法向的关系，判定边界类型：

- **离散边界（生长边界）** ：相对运动背离 → 张裂，形成洋中脊或裂谷，海拔降低（海洋）或形成地堑（陆地）。
- **汇聚边界（消亡边界）** ：相对运动相向 → 碰撞。如果两板块都是大陆地壳，形成造山带（海拔大幅升高）；如果一个是海洋地壳，发生俯冲，形成海沟（极低海拔）和火山弧。
- **转换边界**：相对运动平行于边界 → 水平错动，地形变化较小，但产生线性谷地。

**关键约束**：板块运动必须满足**球面角动量守恒**。PyTectonics 项目在处理板块碰撞时，用角动量守恒来修正碰撞后的速度，而不是简单地让板块停止运动。具体做法是：碰撞发生后，两个板块的角动量矢量相加，得到合并板块的角速度，但碰撞消耗的动能转化为地形抬升的“势能预算”。

#### 1.2.3 高程分配的物理模型

构造高程不是随意分配的，需要遵循**地壳均衡原理**。简化模型如下：

- **大陆地壳**：密度约 2700 kg/m³，厚度 30–70 km。地壳越厚，地表海拔越高。碰撞带的地壳增厚用 `Δh_crust ≈ k × v_rel × t_collision` 估计，其中 k 是增厚效率系数。
- **海洋地壳**：密度约 2900 kg/m³，厚度 5–10 km。洋中脊处地壳最薄、海拔最高（海底约 -2500 m），向两侧随年龄增加而冷却下沉（`depth ∝ √age`）。
- **俯冲带**：海沟深度可达 -8000 至 -11000 m。俯冲板块的年龄和速度决定海沟深度。

一个实用的简化方案是：用**地壳厚度场**作为中间变量，然后通过均衡关系转换为地表高程：

`H = (ρ_mantle - ρ_crust) / ρ_mantle × T_crust - d_ref`

其中 `ρ_mantle ≈ 3300 kg/m³`，`T_crust` 是地壳厚度，`d_ref` 是参考深度。这样，碰撞带的厚地壳自然产生高山，洋中脊的薄地壳自然产生海底高地。


### 1.3 第二层：噪声与扩散精修

构造层输出的高程场分辨率有限（板块 Voronoi 网格通常 0.5°–1°），需要精修到目标分辨率（如 0.1° 或更高）。

#### 1.3.1 多尺度噪声叠加

精修的核心是**分形布朗运动（fBm）** 的叠加：

`H_noise = Σ_{i=0}^{O-1} A_i × noise(f_i × (lon, lat))`

其中 `A_i = persistence^i`，`f_i = lacunarity^i × f_0`。典型参数：persistence = 0.5，lacunarity = 2.0，octaves = 6–10。

噪声函数的选择：

- **Simplex 噪声**：比 Perlin 噪声计算更快，方向性伪影更少，适合作为基础噪声。它使用单纯形网格而非超立方体，在高维下计算复杂度更低。
- **Worley 噪声**（细胞噪声）：产生“块状”地形，适合模拟丘陵和山脊。通过取 `1 - Worley` 并做幂次变换，可以生成尖锐的山脊线。Worley 噪声在形态上比 Simplex 更“独特”，适合需要特定纹理的区域。
- **Ridged fBm**：`H_ridged = Σ |noise_i|`，产生尖锐的山脊，适合山脉精修。

**域扭曲**：在噪声采样时，先对坐标施加一个小幅噪声偏移：`(lon', lat') = (lon, lat) + warp_amp × noise_warp(lon, lat)`。这使地形的沟谷变得蜿蜒，避免直线状伪影。

#### 1.3.2 高斯过程精修

如果需要更强的空间相关性控制，可以用**高斯过程回归**在构造高程的粗网格上做条件模拟。变差函数（variogram）的选取决定地形的“粗糙度”：指数变差函数产生平滑地形，球状变差函数产生有一定特征长度的起伏。

更实用的替代方案是**Terrain Diffusion**。Klisuaiji 的项目直接用扩散模型把构造高程精修为真实地形起伏。扩散模型的优势在于它学习的是真实地形的统计分布，生成的地形在视觉上更“像地球”。具体做法：先用粗分辨率（如 23 km）扩散模型生成宏观轮廓，再用 90 m 或 30 m 模型精修局部细节。需要注意：扩散模型的输出必须**约束在构造层设定的海陆边界内**——海洋区域不能被扩散模型“填平”，山脉区域不能被“削平”。实现方式是将构造高程作为条件输入（conditioning），扩散模型只生成残差项。


### 1.4 第三层：侵蚀模拟

#### 1.4.1 水力侵蚀的物理模型

水力侵蚀是地形“真实感”的关键来源。推荐采用**浅水方程 + 管道模型**的简化方案。

**管道模型**的核心思想：把每个网格单元看作一个“水柱”，相邻单元之间的水通过“虚拟管道”流动。管道中的流量 Q 由两个因素驱动：**水头差**（相邻单元的水面高度差）和**地形坡度**（底部高程差）。

```
Q_pipe = A × sign(Δh) × sqrt(|Δh|) × width
```

其中 `Δh` 是水头差，`A` 是管道截面积系数，`width` 是管道宽度。这是浅水方程的简化形式，在计算上远比求解完整的 Navier-Stokes 方程高效。

水的流动引起**侵蚀和沉积**：

- **侵蚀速率**：`E = K_e × |Q| × slope × (1 - sed_capacity / max_sed)`，水流携带的沉积物越少、流速越快，侵蚀越强。
- **沉积速率**：`D = K_d × (sed - sed_capacity)`，当水流携带的沉积物超过其搬运能力时，多余部分沉积。
- **沉积物输运**：`∂sed/∂t + ∇·(sed × v) = E - D`，这是一个对流方程，可以用半拉格朗日方法或显式差分求解。

Xing Mei 等人的经典论文证明了该方法可以完全在 GPU 上实现，并且能够产生“河流曲流、低丘沉积物冲刷、天然泉水和后退瀑布”等真实地貌特征。

**热力侵蚀**：模拟坡面物质在重力作用下的下滑。当相邻单元的坡度超过**休止角**（talus angle，通常 30°–45°）时，物质从高处向低处转移。这是一个扩散过程，可以用简单的迭代松弛来求解：每个时间步，检查所有网格对，如果坡度超限，按比例转移高程。

#### 1.4.2 河流网络生成

水力侵蚀自然会产生汇流路径。为了得到清晰的河流网络，可以在侵蚀模拟完成后，用**D8 算法**（或 D-infinity 算法）从每个网格单元沿最陡下降方向追踪水流路径，累积流量超过阈值的单元标记为河流。

河流的宽度可以用**水力几何关系**估计：`w ∝ Q^{0.5}`，深度 `d ∝ Q^{0.4}`。这比随意设定宽度更符合水力学规律。

**关键约束**：河流必须从高海拔流向低海拔，不能出现“逆流”。侵蚀模拟后的高程场如果存在局部洼地（被侵蚀产生的封闭盆地），需要用**洼地填充算法**处理，确保每个单元都有到海洋的下降路径。


### 1.5 球面网格的选择

这是整个方案中最容易被忽视但影响最大的技术决策。

**等经纬度网格的问题**：在高纬度地区，经线收敛导致网格单元面积急剧缩小（在极点附近趋近于零）。这会造成：
- 数值不稳定性（CFL 条件在高纬度变得极严格）
- 虚假的极地地形聚集
- 计算资源浪费

**推荐方案：立方球网格（Cubed-Sphere）**

将球面投影到立方体的 6 个面上，每个面用规则网格离散化。优点：
- 单元面积接近均匀（最大/最小面积比约 1.5，远优于经纬度网格的无穷大）
- 没有极点奇点
- 规则网格结构，适合 GPU 和 NumPy 矢量化
- 相邻单元的邻接关系简单（每个面内部是四邻域，面与面边界有固定映射）

**备选方案：HEALPix 网格**

HEALPix 具有严格的等面积性和层次化嵌套结构，被 ICON 和很多新一代气候模型采用。它的层次结构（nside 参数）天然支持多分辨率，非常适合 LOD 渲染。缺点是邻接关系不如立方球规则，实现稍复杂。OctaHEALPix 变体用单个方阵表示整个球面，更适合深度学习模型（如基于 UNet 的扩散模型）。

对于这个项目，建议**地形生成阶段用立方球网格**（规则、易并行），**气候模拟阶段用 HEALPix**（等面积、谱方法友好）。两者之间用插值转换。


### 1.6 地理保真度的验证标准

生成的地形需要满足以下检验：

1. **海陆比**：陆地面积占比应可配置（地球约 29%，但虚拟世界可以任意设定）。
2. **山脉分布**：山脉应集中在板块边界，特别是汇聚边界。大陆内部不应出现无成因的高山。
3. **河流拓扑**：河流必须形成树状网络，无环，从分水岭流向海洋或内流盆地。
4. **坡度分布**：坡度应服从合理的统计分布，不应有大量接近垂直的悬崖（除非是构造断层）。
5. **海岸线分形维数**：真实海岸线的分形维数约为 1.2–1.5，可以用盒计数法验证。
6. **高程-面积关系**：高程的频率分布应呈现双峰（大陆架和大陆），类似于地球的“双峰”分布。


## 二、程序加速策略

### 2.1 加速的总原则

加速的优先级是：**算法优化 > 并行化 > 编译加速 > GPU > IO 优化**。不要一上来就用 C++ 重写，应该先 profile 找到热点，然后判断热点属于哪一类。

对于这个项目，计算热点通常集中在：
- **地形生成**：噪声叠加、侵蚀迭代（网格上的 stencil 计算）
- **气候模拟**：温度/气压/风场的空间插值和梯度计算、洋流的稳态求解
- **可视化**：3D 网格的渲染和 LOD 切换


### 2.2 Python 层优化

**矢量化优先**。所有在经纬度网格上的操作都应该用 NumPy 数组运算表达，消灭 Python 级 for 循环。例如，计算温度场的海拔递减：

```python
# 差
for i in range(nx):
    for j in range(ny):
        T[i,j] = T_base[i,j] - 0.0065 * elevation[i,j]

# 好
T = T_base - 0.0065 * elevation  # 广播，C 级速度
```

**内存布局**。对于立方球网格，每个面内部的数组应该用 C-contiguous（行优先）布局，使最内层循环（通常是经度方向）连续访问内存。如果需要在面之间传递数据，考虑将所有面的数据打包到一个 3D 数组 `(6, ny, nx)` 中，face 索引在最外层。

**避免临时数组**。在循环中反复分配大数组是性能杀手。使用 `out=` 参数或预分配的缓冲区：

```python
# 好
np.multiply(a, b, out=buf)
np.add(buf, c, out=result)
```


### 2.3 Numba JIT 编译

Numba 是最容易上手的加速工具，对规则网格上的循环特别有效。

**适用场景**：噪声生成、侵蚀迭代、D8 汇流累积、Köppen 分类等逐网格计算。

**实际效果**：Icelandic-Aurora 项目用 Numba JIT 编译噪声计算，实现了 **22 倍加速**（256×256 网格从约 16.7 秒降至 0.76 秒）。xdem 库用 `@numba.njit(parallel=True)` 加速地形窗口分析，在大网格上获得了约 **10 倍加速**。

**关键技巧**：
- 用 `@njit(parallel=True, fastmath=True)`。`fastmath` 允许浮点运算重排，对噪声和侵蚀计算安全且有效。
- 用 `prange` 替代 `range` 实现并行循环。
- 用 `cache=True` 缓存编译结果，避免每次运行都编译。
- 避免在 njit 函数中创建 Python 对象（列表、字典），用固定大小的 NumPy 数组替代。
- 对于侵蚀模拟中的迭代，将整个迭代循环放在 njit 函数内部，而不是在 Python 层调用 njit 函数 N 次。

**局限性**：Numba 对不规则的球面 Voronoi 邻接关系支持不好。Voronoi 的最近邻查询应该用 SciPy 的 KDTree 或自实现的球面空间索引，在 Python 层完成，把结果（邻接表）传给 Numba 函数做迭代计算。


### 2.4 JAX 与 GPU 加速

JAX 是这个项目中最有潜力的加速工具，特别适合需要长时间积分的**气候模拟**。

**实际案例**：Veris 海冰模型用 JAX 作为后端，在**高端 GPU 上的单进程性能相当于在数百个 CPU 核心上运行的并行 Fortran 参考实现**，同时能耗大幅降低。LEX 大涡模拟模型也用 JAX + GPU 实现了大气湍流的实时模拟，并利用 JAX 的自动微分能力训练了深度学习 SGS 模型。

**适用模块**：
- 温度场和气压场的**时间积分**（如果需要瞬态模拟）
- 洋流的**稳态求解**（用 JAX 的 `lax.custom_linear_solve` 或迭代求解器）
- 降水的**对流参数化**（可以用 `vmap` 批量计算不同参数下的结果）
- **自动微分**：如果需要做参数优化（如“调整太阳常数使全球均温达到 X”），JAX 的 `grad` 可以直接给出梯度，用梯度下降求解，远比有限差分高效。

**与 Numba 的分工**：
- **Numba**：地形生成（噪声、侵蚀）、分类规则、单次前向计算
- **JAX**：气候模拟的时间积分、需要自动微分的参数优化、需要 GPU 批量计算的部分


### 2.5 并行化策略

**多进程（joblib / multiprocessing）** ：最直接的并行方式是“参数扫描”——同时生成多个不同种子的世界。用 `joblib.Parallel` 可以轻松实现：

```python
from joblib import Parallel, delayed
results = Parallel(n_jobs=-1)(
    delayed(generate_world)(seed) for seed in seeds
)
```

**域分解 + MPI（mpi4py）** ：对于单个高分辨率世界的气候模拟，如果网格太大无法放入单机内存，需要按纬度带或立方球面分块，用 MPI 交换边界数据。mpi4py 提供了 MPI 的 Python 绑定，支持 NumPy 数组的直接通信（`comm.Send` / `comm.Recv`）。

**重要建议**：**不要一开始就做域分解**。先把单机单进程的版本跑通，用 1° 分辨率（约 65k 单元）验证物理正确性，再逐步提高分辨率。只有当单个世界的网格超过 100 万单元时，才需要考虑 MPI 域分解。


### 2.6 数据与 IO 优化

气候数据量很大：一个 0.1° 分辨率的全球网格约 650 万个单元，如果存储 10 个变量、2 个季节、每个变量 4 字节，单次快照约 520 MB。如果保存时间序列，数据量迅速膨胀。

**存储格式推荐**：

- **Zarr**：分块、压缩、支持并行读写，云原生友好。实验表明，合理的分块策略可以实现 **5 倍更少的块读取和 6.3 倍更低的中位延迟**，相比仅基于几何的 Zarr+Xarray 管线。
- **NetCDF4 / HDF5**：如果只在本地使用，NetCDF4 在 POSIX 文件系统上的读取性能很好。

**缓存策略**：
- 地形数据一旦生成，用 Zarr 存储，后续气候模拟直接读取，不重复生成。
- 太阳辐射的日月位置可以用解析公式计算，不需要存储查找表（但如果计算量确实大，可以预计算一年的辐射场缓存）。
- Köppen 分类的中间结果（月温度、月降水）应该缓存，因为分类规则调整时不需要重新计算气候场。


### 2.7 实际加速路线图

| 阶段 | 优先级 | 措施 | 预期效果 |
|------|--------|------|---------|
| **第一步** | 必须 | NumPy 矢量化，消灭 Python 循环 | 基础加速，通常 10–100× |
| **第二步** | 必须 | Numba JIT 编译地形生成和侵蚀热点 | 额外 10–20× |
| **第三步** | 推荐 | JAX 加速气候模拟的时间积分 | GPU 上可达 50–100×（相对单 CPU） |
| **第四步** | 按需 | 多进程参数扫描（joblib） | 线性加速（受核心数限制） |
| **第五步** | 按需 | Zarr 分块存储 + 缓存 | 减少 IO 等待，支持增量计算 |
| **第六步** | 大规模 | MPI 域分解（mpi4py） | 仅当网格 > 10⁶ 单元时考虑 |

**一句话总结**：地形生成用 Numba + NumPy 就够了；气候模拟用 JAX + GPU；多世界并行用 joblib；存储用 Zarr。不需要写 C++。
