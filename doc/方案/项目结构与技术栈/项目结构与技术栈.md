# 项目结构与技术栈

## 一、总体架构设计原则

本项目是一个**计算密集型**的科学模拟系统，代码量预计在 **5万–15万行** 量级，涉及地形生成、辐射传输、流体动力学、生态分类、可视化等多个学科领域。项目结构必须满足以下约束：

**模块化与可组合性**。每个物理模块（地形、辐射、大气、海洋、降水、分类）必须是**独立可测试**的单元，通过明确定义的接口交换数据。模块之间不能有隐式依赖。

**种子确定性**。整个系统由**单一随机种子**驱动。相同种子 + 相同参数 = 完全相同的结果。所有随机数生成器（RNG）的状态必须可序列化和恢复。

**分级分辨率**。系统支持从 10°（快速预览）到 0.1°（详细分析）的多级分辨率。每个模块在低分辨率下必须能快速跑通，高分辨率下用 GPU 加速。

**数据驱动管线**。各阶段之间通过**网格状态对象**（GridState）传递数据，而非松散的字典。网格状态对象包含所有物理量，支持序列化（Zarr）、切片、插值和可视化。

**Apple Silicon 原生**。在 MacBook Pro 2024 上，核心计算用 **MLX**（Metal GPU），CPU 并行用 **Numba**，数据存储用 **Zarr**，渲染用 **VTK 9.7 Metal 后端 + PyVista**。

## 三、核心数据模型

### 3.1 GridState 网格状态对象

`GridState` 是整个系统的**核心数据结构**，承载所有物理场。它必须满足：

- **类型安全**：每个物理量有明确的单位、范围和默认值
- **内存高效**：用 NumPy 或 MLX 数组存储，避免 Python 对象开销
- **可序列化**：支持 Zarr/NetCDF 读写
- **可切片**：支持区域提取和分辨率转换

```python
from dataclasses import dataclass, field
import numpy as np
import mlx.core as mx

@dataclass
class GridState:
    """虚拟世界的完整状态"""
    
    # ===== 网格元数据 =====
    nlat: int
    nlon: int
    resolution: float          # 度
    grid_type: str = "latlon"  # latlon / cubed_sphere / healpix
    
    # ===== 地形层 =====
    elevation: mx.array = None       # (nlat, nlon) 海拔 m
    is_ocean: mx.array = None        # (nlat, nlon) bool
    ocean_depth: mx.array = None     # (nlat, nlon) m
    terrain_type: mx.array = None    # (nlat, nlon) int8
    
    # ===== 辐射层 =====
    S_TOA_jan: mx.array = None       # (nlat, nlon) W/m²
    S_TOA_jul: mx.array = None
    OLR: mx.array = None             # (nlat, nlon) W/m²
    
    # ===== 温度层 =====
    T_jan: mx.array = None           # (nlat, nlon) °C
    T_jul: mx.array = None
    T_annual: mx.array = None
    T_surface: mx.array = None
    T_soil: mx.array = None          # (nz, nlat, nlon)
    
    # ===== 气压与风场 =====
    pressure_jan: mx.array = None    # (nlat, nlon) hPa
    pressure_jul: mx.array = None
    u_jan: mx.array = None           # (nlat, nlon) m/s
    v_jan: mx.array = None
    u_jul: mx.array = None
    v_jul: mx.array = None
    
    # ===== 洋流 =====
    ocean_u: mx.array = None         # (nlat, nlon) m/s
    ocean_v: mx.array = None
    ocean_temp: mx.array = None      # SST °C
    
    # ===== 降水 =====
    P_jan: mx.array = None           # (nlat, nlon) mm/month
    P_jul: mx.array = None
    P_annual: mx.array = None
    evaporation: mx.array = None
    
    # ===== 分类层 =====
    climate_code: mx.array = None    # Köppen int8
    biome: mx.array = None           # int8
    soil_type: mx.array = None       # int8
    agriculture: mx.array = None     # int8
    
    # ===== 派生层 =====
    SOC: mx.array = None             # 土壤有机碳
    pH: mx.array = None
    CEC: mx.array = None
    NPP: mx.array = None
    
    # ===== 元数据 =====
    seed: int = 0
    planet_params: dict = field(default_factory=dict)
    timestamp: str = ""
```

## 五、如何保证合理性

### 5.1 物理因果链闭合

系统的每个模块都建立在前一模块的输出之上，形成**完整的因果链**：

```
行星参数 → 辐射强迫 → 地表能量 → 大气动力学 → 风应力 → 洋流
    ↓                                              ↓
    地形生成 → 气候场 → 降水 → 生物群系 → 土壤 → 农业
```

**因果链闭合检验**：任何环路（如冰-反照率反馈、海气耦合）的增益必须小于1（稳定），或恰好为1（中性），或大于1但被非线性饱和机制限制。

### 5.2 守恒律优先

在每个模块的数值方案设计之前，明确保留哪些守恒律：

| 守恒律 | 数学形式 | 保留方式 |
|--------|---------|---------|
| 能量 | \( \frac{d}{dt}\int(c_p T + L q + \Phi) dm = \text{净辐射} \) | 有限体积 + 能量守恒时间积分 |
| 质量 | \( \frac{d}{dt}\int \rho dV = 0 \) | 通量形式 + 边界条件 |
| 角动量 | \( \frac{d}{dt}\int(\Omega R^2\cos^2\phi + uR\cos\phi) dm = \text{力矩} \) | 谱方法 + 对称离散 |
| 位涡 | \( D[(\zeta+f)/h]/Dt = 0 \) | 涡度守恒格式 |
| 水量 | \( \int E dA = \int P dA \) | 源汇平衡 |

### 5.3 分层验证

**第一层：单元测试**。每个物理模块有独立的单元测试，验证数值方案的正确性（如开普勒方程求解器的精度、Marching Squares 的拓扑正确性）。

**第二层：集成测试**。验证模块之间的接口正确性（如辐射传输输出的加热率是否被大气动力学正确读取）。

**第三层：验证测试**。用 Held-Suarez、Aquaplanet 等标准基准测试验证物理保真度。

**第四层：地球对比**。在地球参数下运行完整管线，与真实地球观测数据对比。

### 5.4 种子确定性

所有随机数生成器（RNG）的状态必须可序列化和恢复：

```python
class DeterministicRNG:
    """确定性随机数生成器"""
    def __init__(self, seed: int):
        self.seed = seed
        self.rng = np.random.default_rng(seed)
        self._state_history = []
    
    def get_state(self):
        return {
            'seed': self.seed,
            'rng_state': self.rng.bit_generator.state,
            'history': self._state_history
        }
    
    def set_state(self, state):
        self.seed = state['seed']
        self.rng.bit_generator.state = state['rng_state']
        self._state_history = state['history']
```

每个模块在使用随机数时，必须**显式记录**种子和调用顺序，保证相同种子产生完全相同的结果。

### 7.3 MacBook Pro 2024 专用优化

**统一内存架构**：Apple Silicon 的 CPU 和 GPU 共享同一物理内存，MLX 数组与 NumPy 数组之间的转换开销极小。建议从地形生成到气候模拟到地表系统输出全程尽量保持数据在 MLX 数组中，仅在保存到磁盘（Zarr）或与外部库（Matplotlib、PyVista）交互时转换到 NumPy。

**精度策略**：GPU 路径统一使用 **Float32**。M4 GPU 的 Float32 吞吐量远高于 CPU 上的 Float64。温度场保留约 7 位有效数字，在 -100°C 到 +100°C 范围内精度约 0.0001°C，完全满足气候模拟需求。

**核心求解器选择**：
- **MLX**：大气动力学、海洋环流、辐射传输、分类（规则判定）
- **Numba**：地形生成、侵蚀模拟、流线积分（串行依赖操作）
- **VTK 9.7 Metal + PyVista**：3D 可视化
- **JAX + jax-metal**：备选（稳定性待验证），需要自动微分时使用

**多世界并行**：用 `joblib.Parallel(n_jobs=12)` 在 16 核 CPU 上并行生成多个世界。每个进程负责一个世界的完整生成管线。对于需要 GPU 加速的单个世界，串行生成，每个世界用 MLX GPU 加速内部计算。

## 十、实践建议

**先粗后细**。在 10° 分辨率上跑通完整管线，验证物理正确性。然后用 5°、2°、1° 逐步提高分辨率。

**Profiling 优先**。用 `cProfile`、`py-spy` 和 `scalene` 找热点。通常 90% 的时间在少数几个 kernel 中。先优化这些 kernel，不要盲目重写全部代码。

**缓存一切可以缓存的**。地形、辐射场、月气候统计量都是静态的，用 Zarr 缓存，避免重复计算。

**与真实地球对比**。在地球参数下运行完整管线，将输出的气候图与真实地球数据对比。如果撒哈拉、亚马逊、西伯利亚针叶林的位置大致正确，说明管线物理合理。

**自动化验证**。将验证管线集成到生成流程中，每次生成世界后自动运行验证，输出报告。

**一句话总结**：Python 编排 + NumPy/xarray 矢量化 + Numba JIT（CPU 热点）+ MLX GPU（核心求解器）+ Zarr 缓存 + VTK Metal（3D 渲染）。先 profile，再优化算法，最后才重写核心。C++ 只是编译内核的一种，本项目更适合 Python 原生 + Apple Silicon 原生加速。
